# داشبورد عملکرد اپراتورها (SLA Ops Dashboard)

داشبورد آنلاین چندفایلی که مستقیماً از فایل اکسل SLA ساخته می‌شه و با هر بار آپدیت اکسل، به‌صورت خودکار روی وب هم به‌روز می‌شه.

## ساختار پروژه

```
sla-dashboard/
├─ index.html                     ← صفحه‌ی اصلی
├─ css/style.css                  ← استایل + تعریف فونت IRANSans
├─ js/script.js                   ← نمودارها، جدول، جست‌وجو/فیلتر/مرتب‌سازی
├─ data/data.json                 ← داده‌ی تولیدشده از اکسل (خودکار آپدیت می‌شه)
├─ fonts/                         ← اینجا فایل‌های مجاز IRANSans رو قرار بده (fonts/README.md)
├─ scripts/build_data.py          ← تبدیل اکسل → data.json (قابل اجرا روی هر فایل مشابه)
├─ .github/workflows/update-data.yml   ← اکشن خودکار: با هر پوش اکسل، دیتا رو بازسازی می‌کنه
└─ Operators_Sla_Performance.xlsx ← فایل اکسل منبع (باید توی ریشه‌ی ریپو باشه)
```

## راه‌اندازی اولیه روی GitHub Pages

1. یک ریپازیتوری جدید بساز (مثلاً `sla-dashboard`) و کل این پوشه رو داخلش پوش کن — شامل خود فایل اکسل هم می‌شه (کنار `index.html`، توی ریشه‌ی ریپو).
2. Settings → Pages → Source: `Deploy from a branch` → Branch: `main`، پوشه: `/root` → Save.
3. بعد از چند دقیقه: `https://<username>.github.io/sla-dashboard/`

## به‌روزرسانی خودکار — منبع اصلی: گوگل‌شیت زنده

منبع اصلی داده الان یک گوگل‌شیت آنلاینه (نه فایل اکسل ثابت). چیدمانش:

- **شیت:** `Operators Sla Performance` — `https://docs.google.com/spreadsheets/d/1E5OU--FCwpW4dBMxRj9MmuBsKzKzGx76FDZ9AvfRJF0`
- **تب فعال:** «Operators performance» (اولین تب، `gid=0`)
- **دسترسی لازم:** `Anyone with the link – Viewer` (همین الان همینطوره؛ اگه عوضش کنی، Action دیگه نمی‌تونه بخونتش)

چرخه‌ی کار:

1. هر **۱۵ دقیقه** یک GitHub Action (`sync-from-google-sheet`) خودکار اجرا می‌شه
2. اسکریپت `scripts/build_data_from_gsheet.py` نسخه‌ی CSV همون شیت رو می‌خونه (بدون نیاز به لاگین یا API key، چون فقط خواندنیه)
3. `data/data.json` بازسازی می‌شه — شامل جمع حقوق (`total_salary`) و حقوق تک‌تک اپراتورها
4. اگه چیزی تغییر کرده باشه، خودکار کامیت و پوش می‌شه؛ GitHub Pages هم خودکار همون نسخه رو سرو می‌کنه

یعنی کافیه توی خود گوگل‌شیت داده‌ها رو آپدیت کنی — حداکثر تا ۱۵ دقیقه بعد، خودش روی داشبورد آنلاین منعکس می‌شه. برای رفرش فوری (بدون صبر کردن)، از تب **Actions** ریپو روی `Update dashboard data` بزن **Run workflow**.

> اگه بعداً تب فعال شیت عوض شد یا خواستی از یه گوگل‌شیت دیگه بخونه، آدرس `gid` تب موردنظر رو (از URL مرورگر، بعد از `#gid=`) بردار و توی `scripts/build_data_from_gsheet.py` (متغیر `DEFAULT_GID`) یا مستقیم به‌عنوان آرگومان جایگزین کن.

### مسیر جایگزین: آپدیت از فایل اکسل محلی

اگه به‌جای گوگل‌شیت، بخوای فایل اکسل رو دستی جایگزین و پوش کنی، همون مسیر قبلی هنوز کار می‌کنه: فایل `Operators_Sla_Performance.xlsx` رو توی ریشه‌ی ریپو جایگزین کن و پوش بزن — job جدای `sync-from-excel` خودکار اجرا می‌شه و `data/data.json` رو از روی اکسل بازمی‌سازه (توجه: چون هر دو job رو همون فایل خروجی می‌نویسن، هرکدوم آخر اجرا بشه، دیتای نهایی همونه).

## اجرا روی یک فایل اکسل دیگه

اگه بخوای همین ساختار رو روی یه فایل دیگه (مثلاً یک شیت دیگه با همین چیدمان ستون‌ها) اجرا کنی:

```bash
python scripts/build_data.py path/to/other-file.xlsx data/data.json
```

اگه نام شیت‌ها یا ترتیب ستون‌ها توی فایل جدید فرق داره، فقط کافیه ثابت‌های بالای `scripts/build_data.py` (`SHEET_PERF`, `SHEET_BUGS`, `PERF_HEADER_ROW`, `BUG_COLS`) رو با فایل جدید هماهنگ کنی — بقیه‌ی منطق نیازی به تغییر نداره.

اگه می‌خوای اکشن گیت‌هاب هم روی فایل دیگه‌ای اجرا بشه (نه `Operators_Sla_Performance.xlsx`)، مسیر رو توی `.github/workflows/update-data.yml` (هم توی بخش `paths` و هم توی دستور اجرای اسکریپت) عوض کن.

## فونت IRANSans

IRANSans دارای مجوز تجاریه، برای همین فایل فونت خودش داخل این پروژه نیست. توضیحات کامل توی `fonts/README.md`. تا وقتی فایل‌های فونت رو اضافه نکردی، سایت خودکار با فونت جایگزین (Vazirmatn) نمایش داده می‌شه — چیزی خراب نمی‌شه.
